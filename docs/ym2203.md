# YM2203 (OPN) notes

The YM2203 is a three-channel FM chip with an AY-3-8910-compatible SSG and
two general-purpose I/O ports.  Furnace calls it `YM2203` (system id `0x8d`)
and exposes six channels: **FM 1-3** then **PSG 1-3**.  The SSG is part of
the same workstation, not a separate AY chip, so it uses the same Furnace
system and the PSG channels right after the FM ones.

## VGM stream

| What | Where |
| --- | --- |
| Clock | header `0x44`; bit 30 means a second YM2203 instance |
| FM writes | command `0x55`, register `>= 0x20` |
| SSG writes | command `0x55` (or `0xA5` for the second chip), register `0x00-0x0F` |
| Second chip FM/SSG | command `0xA5` |

`vgm.py` splits every write into `ym2203` (FM) and `ym2203_ssg` (SSG) so the
FM model never confuses the SSG register bank with FM operators.  The loader
accepts an out-of-spec `0xA5` on a single-chip log as chip 0 and warns, which
is how some old rips store the SSG port.

The clock is passed to Furnace as `customClock=<hz>` unless it is the
3,579,545 Hz default.  A dual log becomes two consecutive `0x8d` systems,
each with its own clock flag.

## Channel layout

One standard YM2203 uses six module channels:

```
0-2   FM 1-3
3-5   PSG 1-3
```

A track that writes the channel-3 per-operator frequency registers
(`0xA8-0xAE`) uses Furnace's **YM2203 Extended Channel 3** system instead
(system id `0xb6`, nine channels):

```
0-1   FM 1-2
2-5   FM 3, one column per operator (OP1-OP4)
6-8   PSG 1-3
```

Two chips occupy nine channels each, chip 0 then chip 1.  Sample chips and
SCC/AY chips, when present, start after the complete YM2203 block.

Furnace's ext platform does not agree with itself about the four operator
columns: column `c` writes its **frequency** to operator `(1,2,0,3)[c]`, its
**instrument parameters** from operator `(0,2,1,3)[c]`, but its **key mask**
bit `c`.  A single column therefore cannot carry the right note, timbre and
key for one hardware operator.  The converter compensates by activating all
four columns on every channel-3 key-on:

- the note on column `c` is the base f-num of source operator
  `(1,2,0,3)[c]`, so the platform writes it to that operator;
- the instrument copy for column `c` carries the source patch's operator
  `(0,2,1,3)[c]`, which is the operator the platform's parameter write
  targets;
- when a source operator is not in the `0x28` key mask, that operator's TL
  is set to 0x7F in the copy, so keying all four columns leaves it silent.

The `.fur` channel names follow the operator whose frequency the column
carries (`FM 3 OP1` is column 2, `FM 3 OP2` is column 0, and so on).  This
makes the exported per-operator frequencies match the source; the pattern
shows all four operators instead of one approximated channel.

## FM notes and pitch

Furnace runs its YM2203 platform with the module's **linear pitch** mode
(the converter writes the linear-pitch compatibility default).  In that mode
a pattern note is `note << 7` engine pitch units, E5 adds `(value - 0x80)`
units of 1/128 semitone, and a pitch macro adds in the same units before the
platform converts the note to an f-num/block.  This is unlike the YM2151's
KC/KF model where E5 is a 1/64-semitone register unit.

The converter therefore:

1. snapshots the block/f-num registers at each `0x28` key-on;
2. chooses the equal-tempered note whose f-num is nearest in the same
   clock, and puts the remainder into E5 as 1/128-semitone units;
3. follows later f-num writes with a **pitch macro** on an instrument copy
   (`_bind_fm_pitch`).  The macro is a signed 16-bit sequence at one entry
   per module tick, so vibrato, ramps and slides survive inside the note.
   The first entry is zero; the note's E5 already holds the key-on pitch.

A note is created when a key-on mask adds an operator.  Key-off (`0x28`
with mask 0) creates a NOTE_OFF row except when a new key-on follows within
two samples (a retrigger must not cut the new note).  A key-on with only some
operators masked gives the unkeyed operators TL 0x7F so they stay silent.

Driver ticks that only touch timers (Iron Horse writes `0x27=0x39/0x3b`
every frame) are ignored.

### Octave convention and carrier MULT

The base note is the source channel's f-num/block, named with Furnace's
note convention (`furnace_note_name`: note 60 = C-0, so note 96 = C-3).
At 1.5 MHz a block-3 f-num 1646 is **C-3 / 130.81 Hz**.

A YM2203 patch can have carriers at different MULT values.  The pattern
note is labelled at the octave of the **loudest keyed carrier** (lowest TL;
equal-TL carriers tie-break to the higher power-of-two), and a constant
pitch macro cancels the relabel exactly:

- one octave up: `-1536` macro (1/128-semitone units);
- one octave down (MULT=0 / 0.5): `+1536`;
- two octaves up (uniform MULT=4): `-3072`, and so on.

The cancellation is written for **every** patch, mixed carriers included.
A mixed patch such as carriers 4x + 2x must not move the whole channel: the
source f-num, block, key scaling, envelopes and the balance between the two
carriers are preserved.  Only the note label follows the audible lead.  If
the loudest carrier is not an exact power of two (MULT=3/5/6/...), the note
stays at the channel f-num and no macro is added.  Unkeyed operators arrive
with TL=0x7F and are ignored, so a silent MULT=2 operator cannot transpose
the channel.

If you edit such an instrument, keep the constant pitch macro together with
the relabelled note; removing only one changes the sounding pitch.  The
tests `test_mixed_carrier_labels_without_moving_the_audio`,
`test_loudest_carrier_sets_the_label` and
`test_uniform_carrier_keeps_the_channel_octave` lock this down.

### Extended channel 3 (FM3EX)

Register `0x27` bit 6/7 selects CSM / 3-slot operation.  A driver then
writes per-operator f-nums for channel 3 at `0xA8-0xAA` / `0xAC-0xAE`
(operators 1-3; operator 4 keeps the normal channel f-num).  The converter
emits Furnace's YM2203 Extended Channel 3 system (`0xb6`) and activates all
four operator columns at every channel-3 key-on, using the note/parameter
routing described above.  Each column gets its own f-num and its own pitch
macro when the driver moves that operator mid-note.  The four columns are
combined by the shared algorithm, exactly as the hardware does.  The SSG
voices move from channels 3-5 to 6-8 in this layout.

CSM timer key-ons that the chip generates internally are still not
synthesized; explicit `0x28` key-ons are.  A track that uses 3-slot mode for
part of its length uses the extended system for the whole track; channel-3
notes outside 3-slot mode feed all four columns the same normal f-num.
Operators absent from the source `0x28` mask are keyed with TL=0x7F so they
stay silent.

## FM instruments

The `.fur` instrument is type 1 (`INS_FM`, OPN), not the YM2151's OPM type.
Operators are stored in YM2203 register order (`0x30/0x34/0x38/0x3c`), which
is also Furnace's internal FM order.  The INS2 `FM` feature carries:

| Register | Feature field |
| --- | --- |
| `0x30` DT/MULT | `dt` / `mult` (Furnace's DT table mapping) |
| `0x40` TL | `tl` |
| `0x50` KS/AR | `rs` (bits 6-7) and `ar` |
| `0x60` AM/D1R | `am` and `dr` |
| `0x70` D2R | `d2r` / `sr` (5 bits) |
| `0x80` SL/RR | `sl` / `rr` |
| `0x90` SSG-EG | `ssgEnv` |
| `0xB0` FB/ALG | `fb` / `alg` |

There is no DT2 field on the YM2203 and the converter leaves it zero.
Carrier operators get KVS=2 so the pattern volume column scales the audible
operators; modulators keep KVS=0.  The instrument `block` field stays 0 so
the pattern note chooses the octave.

## SSG

The SSG is converted through the same AY-8910 model as a stand-alone AY chip
but with Furnace's YM2203 divider of **16** (a stand-alone AY uses 8).  The
register bank is the normal AY one: tone periods `0/1`, `2/3`, `4/5`, noise
`6`, mixer `7`, volumes `8-10`, envelope period `11/12`, shape `13`, I/O
`14/15`.  The resulting notes use `DIV_INS_AY` instruments and the ordinary
`20xx-2Fxx` PSG effects (channel mode, noise period, envelope).  The SSG
clock is the YM2203 clock.

Period writes faster than the module tick are handled by raising the tick
rate while keeping the row length, BPM and pattern grid (`_tone_pitch_tick_scale`).
This preserves Commando's fast SSG arpeggios without changing the song's
rows.  Periods below the representable/harmonic range (for example 0 used
as a gate-off by some drivers) are treated as silence, matching Furnace's
own AY gate.

## Verification

The two debug tools understand YM2203:

- `opn_pitch_stream` reads FM block/f-num or SSG tone period and maps a
  module channel to the right chip instance.  In 3-slot mode it follows the
  per-operator registers, so the comparison measures the sounding pitch,
  not the unused normal f-num.
- Runs are only compared while the source channel is keyed (and, for SSG,
  only while a representable tone is actually sounding), so register writes
  in a rest do not look like pitch errors.

The current `VGM_collection/YM2203` tree has 238 default tracks (including
the duplicate Legendary Wings copies under `1. very good`).  A full
source-vs-export pass through Furnace after the carrier/macro fix gives:

- **137 tracks with zero divergent pitch**;
- **11 tracks with under 500 ms** of small pitch divergence;
- **25 tracks with more divergence**, concentrated in the newly added packs
  (Crude Buster, Gunnail, Last Duel, Avengers and Commando) and in a few
  Legendary Wings tracks.  These are separate pitch-model issues (row
  placement, fast SSG ornaments, driver-specific slides), not the carrier
  octave or FM3 routing; they remain to be investigated individually.
- **65 tracks use the YM2203 Ext system**.  The six-channel `div` metric does
  not describe their four operator columns, so they are checked separately.
  Grounseed 31 `Casements` exports the source per-operator frequencies
  `[95, 124, 124, 95]` exactly at the channel-3 key-ons, including the
  workaround for Furnace's ext column order described above.

Iron Horse `04 BGM 1 (Stage X-1)` now measures **0.0 ms** divergent pitch;
the lossless optimizer accepts x1 through x4 and picks x4, with `loss`
matching the analytic baseline at every factor.

The FM key-on pitch, the OPN instrument register state, the YM2203 clock
headers, dual systems, the SSG tone periods, the ext column routing and the
SSG instruments were also checked individually against Furnace's VGM export
in `tests/test_vgm2151fur_ym2203.py`.
