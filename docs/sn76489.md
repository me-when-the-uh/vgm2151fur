# SN76489 (SMS/Genesis PSG)

The SN76489 has three square voices and one noise voice. It has no key-on:
a voice sounds while its 4-bit attenuation is below 15. Furnace's SMS
platform (`0x03`) exposes the same four registers, so the converter maps a
source period through the period pitch table and plays it back with the same
register value. A T6W28 is the stereo Neo Geo Pocket Color variant (`0xBF`).

## Pitch and system flags

Furnace's SMS pitch table uses feeder clock `315000000/88` and divider 64.
The converter writes `noEasyNoise=true` in the system flags. Furnace's
default "easy noise" shortcut maps every note above roughly 141 through a
linear approximation and clamps the shortest periods to 0; a channel-3 noise
period below 16 then came back silent or wrong. The converter writes real
periods, so the shortcut must be off.

The system volume defaults to 0.500, and an absolute extra-header volume
entry overrides it. Game Gear stereo uses `chipType=3` plus `08xy` panning.

## Pattern grid

A PSG-only log is driven by a 50/60 Hz write loop. The note-onset estimate
can land a few percent away from that loop, so rows slowly slide across the
writes and every so often two writes (a volume step and the next note, for
example) fall on one row. A volume column changes on the row's first tick and
cannot carry `EDxx`, so one of the two events was pulled back to the row
start or dropped.

`analyze._snap_psg_write_lattice` therefore keeps a whole number of rows per
SN76489 write: one row per write when the grid is near the write interval,
or the same fractional split it measured (for example four rows per write).
The 16th-note highlight is scaled by the same factor, so the BPM and the
tick-per-row setting stay as they were. This runs only for a PSG-only log;
an FM log keeps its FM-derived grid.

Volume steps are placed with `Song.row_of` (nearest row), not the floor row
that `place()` returns for notes. A step near the end of a row stays there
instead of being pulled back up to a full row early.

## Noise

Noise control is register `0xE7`/`0xE3`/`0xE5`-style: bit 2 selects white
noise, bits 0-1 select a fixed rate 0-2 or channel 3's period (3). The note
carries the timbre and pitch, and pattern effect `20xy` carries the white and
channel-3 bits:

- `20xy` x=1 white noise, x=0 periodic; y=1 takes the period from channel 3.
- The fixed rates are selected by the note: `note % 12` is 2, 1, 0 for
  hardware rates 0, 1, 2, matching Furnace's `2 - value` mapping.
- With channel-3 mode the note and its pitch points follow tone generator 3's
  period, which Furnace also writes through `0xC0`.

All three fixed-rate modes are white or periodic variants of the *same*
`20xy` value. A mid-gate rate change (for example mode 4 to mode 6) is
therefore not an effect: Furnace derives the rate from the note. The
collector splits such a gate into a new note with the new rate, exactly like
the source's noise-register write. If the driver changes the rate and mutes
the voice on the same sample, the split note has no duration and is dropped;
the note it replaced still gets its key-off, so the old noise does not ring
until the next key-on.

A channel-3 period jump larger than the 15 semitones an `E8xx` can carry on
one row is also split into a new note, marked legato (`EA01`). The source
changes the period register in one write; a multi-row `E8xx` ramp would slide
through unrelated periods. Legato commits the new note and period without a
key-on, so the noise generator keeps running.

## Repeated notes

A tone driver can retrigger a held note without changing its pitch: it writes
the same 10-bit period again and then a different attenuation on the same
sample. The collector turns that pair into a new note. A period rewrite on
its own, or followed by a volume write that keeps the same level, is register
housekeeping and stays inside the held note.

This matters on the condensed (x2/x3) variants: the retrigger and its first
volume steps can otherwise collapse onto one row, leaving only a volume
column and no visible note-on.

## Sample playback

Some Mega Drive drivers leave a tone voice's period at 0 and stream 4-bit
attenuation values through it at audio rate. The voice is then a DAC, not a
tone. Furnace's SMS platform cannot play samples on a PSG channel, so the
converter renders the stream to 4-bit linear PCM and plays it on a **Generic
PCM DAC** (`0xC0`) system, the same mechanism used for K054539/ES5503
samples.

The recognizer needs a fast volume-write loop while the tone period stays 0.
All eight After Burner II tracks use only voice 0 this way; their writes
arrive every ~8 VGM samples (about 5.5 kHz) with attenuation 5 as the idle
level.

- The body uses the SN76489 2 dB/step curve, subtracts the idle
  attenuation's amplitude, and maps that result onto Furnace's linear 4-bit
  depth: nibble 8 is idle, 0/15 are the negative/positive peaks. Long idle
  holds therefore become silence.
- It is rendered at 22,050 Hz; the source update rate is about 5.5 kHz.
- The stream is split at real rests into attack-to-attack bodies. A rest is
  a run of the exact idle attenuation of at least 256 frames (about 11.6 ms);
  shorter gaps are waveform motion. Every body starts on a non-idle attack
  transient; a continuous passage stays one body instead of being cut in
  mid-wave. The VGM loop point gets its own boundary because playback has to
  resume there.
- Each body keeps its decay and silent tail up to the next attack. The next
  note cuts the tail at the source's own attack time, so a short body never
  loses its tail when no following note arrives.
- A segment shorter than 128 packed bytes (256 frames) is not banked as its
  own sample. At 4-bit amplitude resolution it is a noisy fragment, so it is
  folded into the previous body's tail until a real attack is reached.
- Bodies are deduplicated exactly. When a shorter attack is a prefix of a
  longer one, the short play reuses the **longest** body: the following note
  cuts it at the right time, and the quiet tail survives when it does not.
  This is the same largest-variant prefix rule as the YM2612 attack splitter.
- A body that contains only the idle attenuation is dropped; rests do not
  create silent samples or pointless note cuts.
- One Generic PCM DAC channel plays the chunk notes through a 120-slot
  sample-map instrument (multiple instruments when the track needs more than
  120 bodies).
- The body is normalized to one voice's amplitude, and the system volume is
  the player's SN76489 chip level (0.500 by default) divided by the
  four-voice mixer share: **0.125**. Using 0.500 made the DAC four times too
  loud; 0.25 would be the voice share before the chip's own 0.500 level.
- `--melody-only` still drops the sample system, like the other sample chips.

The rendered sample is mono; the source PSG has no pan.

## Limits

- Furnace's shortest period table entry is 2. Source periods 0 and 1 clamp to
  it.
- Sub-frame gates shorter than `PSG_MIN_NOTE` (100 samples) are dropped and
  counted in the conversion warning.
- The T6W28's noise select/extra period is handled as a period change, not a
  new note; its two halves are already a stereo pair.
