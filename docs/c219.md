# Namco C219

C219 is the 16-voice C140-family PCM chip used by Namco NA-1/NA-2. VGM uses
the same `0xD4` command as the C140, with header `0xA8` for the clock and the
type byte at `0x96` set to 2. The sample ROM is data block `0x8D`; VGMPlay
pair-swaps every C219 ROM payload before loading it, and this converter does
the same.

## Conversion

- Furnace system `0xCF`, 16 columns, instrument type `54` (`INS_C219`).
- Each register block is 16 bytes: volume R/L at `0x00/0x01`, frequency at
  `0x02/0x03`, mode at `0x05`, start/end/loop word addresses at
  `0x06-0x0B`.
- Bank groups select 128 KB banks through `0x1F7` (voices 0-3), `0x1F1`
  (4-7), `0x1F3` (8-11) and `0x1F5` (12-15); the `0x1F8-0x1FD` mirrors are
  handled.
- Playback advances one byte per step. The body is `(end - start) * 2` bytes;
  loop points are likewise word addresses. The source rate is
  `clock * freq / (288 * 65536)`.
- Mode bit 7 is key-on. Unlike C140, bit 6 is **invert**, not retrigger; any
  control write without bit 7 is a key-off. Bit 4 is loop, bit 3 inverts only
  the left output (surround), bit 2 selects noise and bit 0 selects the C219
  mu-law table.
- Noise notes get a silent body of the same window length so their duration
  and loop flag survive; `11xx` selects noise and `12xy` carries
  surround/invert.
- C219 mu-law is decoded to 8-bit linear. Furnace's native C219 depth 12
  stores the compressed bytes, but its upload path uses `length8`, which is
  zero for a C219-depth sample, so only four bytes would reach chip memory.
- Silent constant/DC bodies are dropped instead of taking a sample slot.
- Each source sample bank is kept in its own Furnace 128 KB bank. Trailing
  silence is appended to a one-shot body of the previous bank rather than
  adding a silent padding sample; one-shot playback is unchanged and loop
  points stay inside the original data.

## Playback check

Furnace's C219 uploader reserves `length8 + 4` bytes per body, clamps a body
to one 128 KB bank, rounds an odd length up to even, and moves a body to the
next bank first if its end crosses the boundary. The converter mirrors those
rules when it computes a gap, so the last donor body stops two bytes before
the boundary instead of ending exactly on it (which would make Furnace move
that donor into the next bank and split its source group).

After laying the bodies out, `c219_layout_warnings()` replays the uploader and
the key-ons:

- a body over 128 KB, or a total over 512 KB, is reported because Furnace
  truncates it;
- a looping body that gained trailing bytes is reported because its loop end
  moved;
- a source bank that lands in more than one Furnace bank is reported;
- key-ons are replayed in time order through the four voice groups. Furnace
  writes a group's bank on key-on and key-offs every other *active* voice in
  that group. The check reports each bank switch that would silence another
  voice, with the first sample time and the number of cuts.

These warnings are part of the normal conversion report, so a module that
would lose a sample at playback time is flagged instead of silently sounding
short.

## Pitch and volume

The reference core runs at `clock / 288`; Furnace's C219 core runs at
`chipClock / 1136`. The module writes `customClock` as
`min(100000000, round(clock * 1136 / 288))` and scales sample C-4 rates when
that ceiling is reached. The chip volume is calibrated to VGMPlay's C219
output (1.4x the player's C140-family level), with the song master at 1.0.

## Limits

- A source bank whose sample bodies do not fit in 128 KB cannot be kept
  separate; Furnace then spills into the next bank and may silence other
  voices in that group.
- A log whose unique sample bodies exceed 512 KB is truncated by Furnace.
- Mid-note bank-register changes are not split into a new note; the sample
  body is taken from the key-on bank.
- The C219 output is stereo; the source's independent left/right 8-bit
  volumes are reduced to the volume column plus a 4-bit `08xy` balance.
