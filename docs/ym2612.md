# YM2612 (OPN2) notes

The YM2612 is the six-channel OPN2 core.  It has the same four-operator FM
building blocks and eight algorithms as the YM2203's FM half, plus a second
register bank for channels 4-6, a stereo/LFO-sensitivity register per channel,
and one 8-bit DAC that replaces channel 6.  Furnace calls it `YM2612`
(system id `0x83`, six channels) and its channel-3 split version
`YM2612 Ext` (system id `0xa0`, nine channels).

## VGM stream

| What | Where |
| --- | --- |
| Clock | header `0x2C`; bit 30 means a second YM2612 instance |
| Bank 0 writes | command `0x52` (channels 1-3, global registers) |
| Bank 1 writes | command `0x53` (channels 4-6) |
| Second chip | commands `0xA2` / `0xA3` |
| Key on/off | register `0x28`, channel field `0`-`2` and `4`-`6` |
| Channel 3 special mode | `0x27` bits 6-7 = `01` |
| CSM | `0x27` bits 6-7 = `10` |
| DAC | `0x2A` data, `0x2B` enable |
| DAC data block | `0x67`, type `0x00` (unsigned PCM bank) |
| DAC play stream | `0xE0` pointer, `0x80`-`0x8F` byte + wait |
| DAC stream control | `0x90`-`0x95` (modern; `0x95` one block) |
| Genesis PSG | command `0x50`, one SN76489 serial byte |
| LFO enable/rate | `0x22` |
| Pan / PMS / AMS | `0xB4`-`0xB6` |

The loader stores the chip's 9-bit register address flat: bank 1 reads as
`0x100 + register`, the same index ymfm uses.  The frequency registers are
latched pairs: the high byte (`0xA4`-`0xA6`, `0x1A4`-`0x1A6`, `0xAC`-`0xAE`)
is held until the matching low byte is written.  The analyzer applies the
latch, so a key-on between the two writes sees the hardware's old frequency,
and the committed low write becomes a pitch step on the held note.  The
YM2612's six key-on channels are encoded as `0`-`2` and `4`-`6`; value `3` /
`7` is reserved and ignored.

## Channel layout

A Genesis module uses six YM2612 channels followed by the four SN76489
channels (a second SMS system; system ids `0x83` + `0x03`, ten channels):

```
0-5   FM 1-6 (FM 6 also carries the DAC)
6-8   SN76489 tone 1-3
9     SN76489 noise
```

A source that writes channel 3's per-operator registers (`0xA8`-`0xAE`, with
`0x27` bits 6-7 set) uses Furnace's **YM2612 Extended Channel 3** system
instead (system id `0xa0`, nine channels):

```
0-1   FM 1-2
2-5   FM 3, one column per operator (OP1-OP4)
6-8   FM 4-6
```

The per-operator frequency register pairs are `0xA9/0xAD` (register 0x32's
operator), `0xA8/0xAC` (0x36), `0xAA/0xAE` (0x3A) and the normal `0xA2/0xA6`
(0x3E).  Furnace's ext columns write their frequency in the order
`(op32, op3A, op36, op3E)` and their parameters in the order
`(op32, op36, op3A, op3E)`, so the converter uses the same column routing as
the YM2203 Ext path: `EXT_FREQ_OP = (1, 2, 0, 3)`.  The `.fur` channel names
follow the operator whose frequency the column carries.

CSM mode (bits `10`) also gives channel 3 per-operator frequencies, so the
track uses the Ext layout.  The CSM timer's internal key-ons are not
synthesized; the explicit `0x28` key-ons are.  The report warns when CSM is
seen.

## FM notes and pitch

Furnace's `DivPlatformGenesis` runs the module in **linear pitch** mode with
`fmFreqBase = 9437184` (twice the YM2203's 4720270).  A pattern note therefore
maps to `fnum = round(440 * 2^((note - 57)/12) * (9437184/clock))` with the
note's block shifted out, and the same note number is one octave above a
YM2203's.  `ym2612.py` ports that formula (including the boundary shifts and
the `nbase >> 7` block move for a negative E5), and inverts it to
`(note, E5)` at 1/128-semitone resolution.

A note is created when `0x28` adds an operator bit.  The key-on snapshot
provides the block/f-num, the algorithm/feedback, the operator registers, pan
and PMS/AMS.  Key-off (`0x28` mask 0) creates a NOTE_OFF row unless a new
key-on follows within two samples.  A key-on with only some operator bits
gives the unkeyed operators TL 0x7F so they stay silent.

Frequency writes while a note is held are handled in three ways:

1. **Short held steps** (up to four distinct states, e.g. the driver writes
   the f-num after the key-on, octave switches, percussion bends) become
   `E5xx` fine-tune steps and `E8xx`/`E9xx` whole-semitone transposes on the
   pattern rows.  This costs no instrument and is exact at row resolution.
2. **Slow glides and triangles** with few direction reversals use the same
   row-step encoder at one step per row.  `E5xx` is kept inside its own range
   by emitting the semitone transpose that recentres it, so a slow slope
   moves every row instead of jumping when E5 saturates.
3. **Vibrato and other oscillating motion** becomes a per-tick `pitch2`
   instrument macro on a copy of the timbre instrument.  The macro is a
   signed 16-bit sequence at one entry per module tick (two units per 1/64
   semitone), so the driver's own frequency trajectory plays back exactly.

The first two forms keep a track with thousands of octave-switch notes well
under Furnace's 250-instrument limit.  A vibrato note that cannot get a copy
falls back to the row encoder and reports how many did.

A patch whose loudest carrier uses a power-of-two MULT sounds an octave
above/below the channel f-num.  The note label follows the loudest audible
carrier (lowest TL, tie-break to the higher power of two) and a constant
pitch macro cancels the label move exactly; mixed-carrier balance and the
source f-num are untouched.  This is the same rule as the YM2203.

## FM instruments

The `.fur` instrument is type 1 (`INS_FM`, OPN).  Operators are stored in
YM2612 register order (`0x30/0x34/0x38/0x3c`), which is also Furnace's
internal order in the FM feature:

| Register | Feature field |
| --- | --- |
| `0x30` DT/MULT | `dt` / `mult` |
| `0x40` TL | `tl` |
| `0x50` KS/AR | `rs` / `ar` |
| `0x60` AM/D1R | `am` / `dr` |
| `0x70` SR | `sr` (5 bits) |
| `0x80` SL/RR | `sl` / `rr` |
| `0x90` SSG-EG | `ssgEnv` |
| `0xB0` FB/ALG | `fb` / `alg` |
| `0xB4` PMS/AMS | `pms` / `ams` |

There is no DT2.  KVS=2 is set on every OPN operator: Furnace's KVS test
applies the pattern volume only to real carriers (its `isOutput` table), so
modulators keep their absolute TL.  The instrument `block` field stays 0 so
the pattern note chooses the octave.

Two orderings are easy to get wrong:

* The register pages are S1, S3, S2, S4, while the `0x28` KON mask bits are
  S1, S2, S3, S4.  Register index 0/1/2/3 therefore corresponds to mask bits
  0/2/1/3; a partial key-on must mute S2/S3 using that mapping.
* Algorithm 4's carriers are S2 and S4 (registers `0x38` and `0x3C`), not
  S3/S4.  Furnace's `isOutput[4]` uses the same register order.  Setting the
  carrier normalization and KVS on the wrong pair leaves a real carrier at
  full level and changes both gain and the modulator/carrier balance.

DT1 value 4 is negative zero and is written as 0 (not the +1 that Furnace's
raw DT index 4 would produce).  Non-KON writes at a sample are applied before
its KON writes, so a driver that writes the last patch byte (`0xB4` is common)
just after `0x28` starts the note with the final patch.

Carrier TL is normalised out of the instrument: the carriers are stored at
relative levels (loudest = 0) and the note's volume column carries the
absolute level (`127 - min carrier TL`).  Furnace's `newVolumeScaling` makes
the written TL `clamp(127 - vol + op.tl)`, so this reproduces the source
exactly while a driver that rewrites carrier TL every note no longer creates
one instrument per note.  Mid-note carrier TL writes continue to become
volume-column steps.

PMS/AMS are part of the patch identity, so two notes that differ only in LFO
sensitivity do not share an instrument (the platform writes `0xB4` from the
instrument only when the instrument changes).

## LFO, pan and effects

The chip-wide LFO register `0x22` becomes Furnace effect `10xy`
(`x` = enable, `y` = speed).  Per-channel `0xB4` changes made during a note
become `08xx` (pan), `62xx` (PMS) and `63xx` (AMS) on that channel's rows.
The key-on snapshot carries the initial values.  Note that effect `10xy`
takes the enable bit in the high nibble, so the register's bit 3 is moved
there.

## DAC

Register `0x2B` bit 7 replaces channel 6's FM output with the DAC.  While it
is enabled the converter suppresses FM6 FM notes (they are sample playback
writes, not FM notes).  A log that writes `0x2B` but never sets bit 7 has no
audible DAC at all, so its FM6 key-ons stay FM notes; Contra track 01 is the
reference case.  A log with no `0x2B` write is treated as DAC-enabled, because
some rips omit the register even though the stream is audible.

The collector builds one event model from all three forms:

- old style: `0xE0` read pointer plus `0x80`-`0x8F` play byte and wait;
- direct `0x2A` writes;
- modern `0x92` rate plus `0x95` block plays (type-0 data blocks).

The default is a sequence of **rate-exact PCM chunks**, one FM6 note each.
Words are grouped into phrases at pauses longer than 2,048 VGM samples.
Within a phrase, audio words split at every `0xB6` pan change and into at
most 0.25 s pieces; the track is capped at 240 samples.  The 130-sample probe
loads in 0.6.8.3, a 392-sample slice track fails, and the chunked 75/219/240
modules load.  Each chunk starts at an audio word, ends at its last audio
word plus one trailing `0x80` frame, and plays at
`round(44100 / smallest positive write interval)`.  Every source byte gets a
distinct frame; gaps are the DAC's hold.  A silence-only phrase and leading
silence create no sample and no note.  A same-time burst collapses to its
final value with a warning.

This replaces the previous one-sample-per-phrase default: one note can hold
only one pan.  On Contra 02 the source writes `0xB6=0x40` (right) before the
first audio, `0xC0` (both) later and `0x80` (left) in the middle; the one
phrase was right for the whole track.  The chunks now follow it: track 02 is
75 chunks/notes (57 both, 12 right, 6 left; one 120-slot map), track 04 is
219 (196 both, 23 right; two maps), track 20 is 240 (234 both, 6 right; two
maps).  The first 12 right notes on 02 are the source's intro section.

The old per-run sample-map representation remains available as
`collect_dac(vgm, slices=True)` for editing.  It stores source runs at their
own rate, merges same-row runs, and selects them with note `60 + slot`.  It
is not the default because a dense track produces 1,098-12,624 samples and
Furnace 0.6.8.3 rejects those with `invalid sample count!`, even with map base
0.  The slice mode also drops pure-silence rows and folds a zero tail into
the preceding sample.  The old 22.05 kHz body is `timeline=True` for
comparison only.

The writer uses Amiga sample maps with `first_sample=0`; a nonzero base is
read by the release loader as an embedded sample count and rejected.  The
sample's C-4 rate is corrected for Furnace's reference, so the exported
`0x92` rate is the chunk's natural rate.  Pan is the `0xB6` state at each
chunk start and becomes an `08 xy` effect on that note.

The PSG/SCC/AY instrument base counts the DAC maps exactly once, including
after an FM pitch copy.  A stale module pointed every PSG note at a DAC map
and its PSG was silent while the source noise attenuation was audible; the
current binding uses the `SN`/STD instrument and has a regression test.

## Genesis PSG (SN76489)

The VGM `0x50` byte is a serial SN76489 word: a latch byte carries the
channel (`0`-`3`), register type (tone/volume) and low nibble; a following
data byte carries the upper six tone-period bits.  The converter decodes
three 10-bit tone periods and the noise mode.

The chip has no key-on: a voice sounds while its 4-bit attenuation is below
15.  A gate-on starts a note; a volume-off ends it.  The note's pattern
volume column is `15 - attenuation`.  Mid-note attenuation changes become
volume-column steps.  Period changes while a note is held become the
instrument's pitch macro, so vibrato and slides survive; a period jump of a
semitone or more starts a new note.

Furnace's SMS platform uses the same clock (COLOR_NTSC, 3.579545 MHz) and a
10-bit period with `toneDivider=64`.  A source period is inverted through the
same period table; a note whose base period is an exact match is preferred so
the pitch does not wait for an E5 fine-tune write.  Noise is the SMS noise
channel: note `C-0`/`C#0`/`D-0` select the fixed-rate presets and effect
`20xy` selects white/periodic and channel-3-rate modes.  The PSG is mono; no
pan effect is written.

Extreme periods below the musical table range (period below ~15) clamp to the
shortest representable note, and two PSG notes landing on the same channel
and row still collide.  Those are the remaining PSG approximations; the
reference track 04 has zero settled period and volume mismatches.

The converter's default `.fur` SN76489 chip volume is **0.500** (32/64), not
the reference player's 1.0; an absolute VGM extra-header volume entry still
replaces it.  That keeps the PSG under the FM mix.  `edit --chip SN76489
--value` overrides a finished module without reconverting.

## Verification

`diag.ym2612_pitch_stream` follows the latched f-num for a normal channel and
the per-operator pairs for an Ext column.  `ym2612_keyed_intervals` counts a
channel as sounding only while its `0x28` mask is non-zero (and, for FM6,
while the DAC is disabled).  The `compare` command therefore measures the
sounding pitch, not stale register writes in a rest.

The `VGM_collection/YM2612/Thunder Force IV (Lightening Force)` pack is the
primary reference: all 48 tracks have zero divergent pitch at
0.25 semitone / 60 ms through the real conversion pipeline (loop finding on,
Furnace export), and the largest track uses 22 of the 250 instrument slots.

An instrument audit matched every source `0x28` key-on to the exported
key-on on the same channel within 100 ms and compared the effective operator
state (unused `0x50` bit 5 and `0x60` bits 6-5 are don't-cares; DT=4 is
negative zero).  Over all 48 tracks:

| | current | vgm2fur v0.4.1 |
| --- | --- | --- |
| pitch runs (0.25 st / 60 ms) | 0 | 20 (11.25 s) |
| key-ons matched / total | 64,230 / 64,291 | 60,894 / 64,291 |
| effective field mismatches | 15 (4 TL) | 7,997 (4,204 TL) |

The remaining 61 misses are same-row note collisions/startup notes, and the
15 field differences are mid-note changes or the first partial-patch sample.
The old converter's larger TL count is its main audible difference: its
carrier levels do not match the source on many notes; its 6 tracks with pitch
runs also diverge at up to 1.98 semitones.

The same audit now includes the SN76489.  The full Thunder Force IV set has
80,298 matched key-ons and 133 missed (72 of them PSG).  Its 16,140 PSG notes
have 1,067 settled period and 742 volume differences after a 10 ms settle
window; most are extreme high-period notes or same-row PSG collisions.
Track 04 has zero PSG period and volume differences.  Track 04's isolated
PSG channel 0 render has an envelope correlation of 0.9974, log-spectral
distance 0.0164 and RMS ratio 1.00036 against the source.

The Contra Hard Corps pack (29 tracks) is the DAC reference.  The final
default is a release-capped sequence of rate-exact PCM chunks, one FM6 note
each: tracks 02/04/20 have 75/219/240 samples and notes.  The old slice set
had 1,098/3,054/12,624 samples and 1,105/3,054/12,633 notes after dropping
the pure-silence rows; Furnace 0.6.8.3 rejects that sample count even with
map base 0.  The 130-sample probe loads; the 240-sample chunk track 20
renders a 57,995,896-byte WAV, as do the 75-sample 02 (5,509,576) and
219-sample 04 (16,895,664).  The one-phrase default is gone: its single note
held the first pan for the whole track.

The regenerated chunked `fur/condense.tsv` reports 50,692 keys: 45,177 FM
keys plus 5,515 DAC chunk notes; 0 missed and `psg_miss = 0`.  The 13 field
differences and up to 2,182 ms divergence at 1x are the newly audible PSG
path; the old 45,500/0/0 figure was measured with PSG notes bound to a DAC
map, i.e. silent.  The FM-only Thunder Force IV audit remains 0 divergent.
The 179,831 DAC-note/154,155-slice audit belongs to the explicit slice
representation, not the chunked release path.

Audio on track 04 through `tools/fur_soundcheck.py`: the chunked 219-sample
render has the same 16,895,664-byte WAV as the old timeline; the slice and
old timeline chroma checks were 0.996/0.995 for the module and 0.996 for the

0.9945 for the timeline; 0.101 / 0.9129 for vgm2fur) is historical.

The three Sonic packs (Sonic 2, Sonic 3 and the Sonic 3 prototype; 118 tracks)
passed the earlier 118-track pitch audit with zero divergent pitch on the FM
channels.  The old Sonic PSG silence was not source behavior: the source noise
attenuation is audible, but the module's PSG notes pointed at a DAC sample-map
instrument.  The tone base now counts the DAC maps exactly once (including
after a pitch copy), and a fresh Sonic 01 binds every PSG note to `SN`
(INS_STD).  The noise envelope still writes many volume rows; it is audible.
The 64 missed FM6 key-ons on Emerald Hill are DAC-enabled writes, not lost
notes.  Spot checks of Emerald Hill, IceCap Act 1 and Data Select give zero
pitch runs and near-zero effective operator mismatches; the other 117 tracks
were not re-run for this change.

`pitch_runs` compares only through the exported module's end, so the source's
post-loop tail after a deliberately cut loop does not count as divergence.

The loader uses the sample at the stream's `0x66` as the effective track
length when it disagrees with the header total.  Several Genesis logs declare
a length far past their last command (Sonic 2's Mystic Cave 2P says 56 s but
the stream ends at 12.7 s); the old header length made the exported module
loop while the source still held its last note, which showed up as a false
pitch divergence.

The synthetic tests in `tests/test_vgm2151fur_ym2612.py` cover the latch,
both banks, special/CSM layouts, the LFO, the carrier-TL normalisation,
SN76489 decoding and pitch/gate behaviour, DAC stream collection and PCM
round trips, a Furnace export round trip for the note pitch, operator fields
and LFO, the algorithm-4 carrier order, DT=4, partial KON masks and
same-sample post-KON patch writes, plus two full Thunder Force IV tracks
through Furnace.  The DAC tests cover the chunked default (20 s becomes
>1 and <=240 chunks; the 0.25 s budget; three source pans appear on chunk
notes and `08` effects; a short stream stays one chunk; a long gap splits
audio and drops the silent phrase; a silence-only stream has no notes; the
smallest interval 14,700 Hz; map base 0), the explicit slice mode (direct
`0x2A`, long gaps, held bytes, same-row merges, 130 runs/two maps, pan,
disabled DAC, modern blocks, export round trip, silence-row removal) and PSG
binding to INS_STD; the SN76489 default system volume is 0.500.  Full suite:
384 passed, 1 skipped.
